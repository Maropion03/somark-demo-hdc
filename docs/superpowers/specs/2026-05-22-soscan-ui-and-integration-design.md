## 2. 三套首页风格

**共同基线**:三套都保留 SoMark 品牌识别 —— 纯黑底、橙色 `#FF8C00` 主色、「SoScan」字标 + 三段式 logo mark。三套共享同一套页面流程与后端逻辑,**只在表现层分叉**:首页视觉语言、扫描主按钮、文档卡片处理、标志性动效。

风格当前精确定义到**首页**(真机评测主战场)。结果页 / 扫描页沿用各风格的主题 token(按钮 / 卡片 / 表面质感),不单独出 mockup;StructureRenderer 的解析结果渲染逻辑三套共享。

### A · 流光 Aurora

- **气质**:Apple WWDC 风格的金属流光。冷峻、高级、克制。
- **首页**:纯黑底;顶部立体金属质感「SoScan」字标 + 三段 logo mark;副标「文档解析 · 结构还原」;文档列表为半透明微玻璃卡片;底部橙色光泽胶囊按钮「扫描文档」(带橙色辉光)。
- **标志性效果**:一束柔光以 ~13s 慢循环扫过字标 —— 扫到的字母被照到极亮(近全白),同时字母背后浮现一层**与该字母同形**的光晕(模糊的亮字),光晕天然随字母轮廓变化。无缝循环。
- **ArkUI 实现要点**:金属字 = 文字 + 线性渐变(渐变文字,或退到高清字标图);流光 = 一个亮度蒙版沿 X 轴平移的循环动画;光晕 = 同蒙版的模糊副本。mockup 用 CSS `background-clip:text`,ArkUI 无等价 API —— 若渐变文字 + 蒙版动画达不到效果,退到「字标图 + 高光位移层 + 模糊副本」三层叠加。**实现风险:中**(流光精度是这套的成败点,留足调试时间)。
- 一句话:柔光扫过 · 字母极亮 · 光晕随字母形状变化。

### B · 漾 Fluid

- **气质**:整片缓慢流动的橙色液面。温润、有机、灵动。
- **首页**:深黑底 `#0a0a0c`;顶部三段 logo mark +「SoScan」+ 右侧文档计数;文档列表缩略图为统一中性深色的「鹅卵石」squircle(有机不规则圆角),解析中的那条用橙色水滴图标 + 轻微脉动;**底部整片是流动的橙色液面**(2 条波,慢速错速漂移 ~17s / 27s),「扫描文档」CTA 浮在液面上;全屏无光晕,边缘全是流畅曲线。
- **标志性效果**:底部液面 —— 不是一个按钮形状,而是整个底部区域是一片缓慢起伏的橙色「水」,最多两个浪、慢漂移。
- **ArkUI 实现要点**:液面 = `Canvas` 逐帧绘 2 条贝塞尔波形并循环平移(或两张波形 `Path` 平移);squircle = 四角不等的自定义圆角。**实现风险:低-中**(Canvas 波形动画成熟;注意低端机不掉帧)。
- 一句话:整片流动液面 · 干净无光晕。

### C · 触感 Tactile

- **气质**:真实键盘的拟物质感。沉稳、有重量、可信。
- **首页**:深黑底 `#0c0c0d`;顶部浮雕橙色 logo mark +「SoScan」+ 文档计数;文档列表为有厚度的拟物卡片(顶部高光边 + 底部内阴影 + 硬投影),每条左侧带一颗状态 LED 灯点(已解析=绿、解析中=橙);**底部是一片模拟的实体键盘** —— 灰黑键帽组成键阵,「扫描文档」是其中一颗橙色主键、自然融入;上两行键左右错开(像真键盘错行)、横向略超出屏幕边缘、键阵顶部渐隐。
- **标志性效果**:实体键盘背景 + 橙色主键。质感靠倒角、厚度、硬投影体现,不靠发光。
- **ArkUI 实现要点**:键帽 = 多层 `shadow` 堆叠(内阴影高光边 + 外硬投影);键阵顶部渐隐 = `linearGradient` 蒙版。**实现风险:低**(纯静态样式,无复杂动画)。
- 一句话:真实键盘 · 错行排布 · 橙键融入键阵。

## 3. 工程方案:三个 worktree、三个可同时安装的 app

- **三个 git worktree**,从当前 `main` 切出,分支:`nwk/feat/ui-style-a` / `-b` / `-c`。
- 每个 worktree = 同一套共享后端(扫描、SoMarkApi、DocumentStore、PdfBuilder)+ 不同 UI 皮肤。共享逻辑已在 `main` 基线,三个 worktree 只在表现层分叉,保证合并干净。
- **三个 bundleName**(三个 app 要能同时装一台手机):

  | 风格 | bundleName | app label(桌面名) |
  |---|---|---|
  | A 流光 | `ai.somark.demo.aurora` | SoScan 流光 |
  | B 漾 | `ai.somark.demo.fluid` | SoScan 漾 |
  | C 触感 | `ai.somark.demo.tactile` | SoScan 触感 |

- **三个图标**:评测期临时方案 —— 同一 SoScan 图标 + 右下角小 A/B/C 角标区分;选定后,胜出风格换回唯一正式图标(见 §7)。
- **签名**:每个 bundleName 需各自签名。开发者在 DevEco 里逐个打开三个 worktree、各做一次自动签名(共 3 次一次性 GUI 操作)。每个 worktree build 通过后,我 ping 用户做对应签名。
- `dev.sh` 内硬编码了 `BUNDLE="ai.somark.demo"` —— 每个 worktree 的 `dev.sh` 改成自己的 bundleName。
- **选定流程**:三个都 build 通过 → 开发者逐个签名装机 → 真机对比 → 选定 → 胜出 worktree 合回 `main` 作最终 UI、bundleName 改回 `ai.somark.demo`;另两个分支保留作记录。

## 5. API key 安全方案

(回应用户「测试阶段没关系,上线时不能暴露,你给方案」。)

**问题**:客户端 app 无法安全保存密钥。HAP 包可被反编译,`SOMARK_API_KEY`、`DASHSCOPE_API_KEY` 都能被提取 —— 这是两个 key 共同的问题。

- **阶段一(测试 / 演示期,现在)**:key 放 `config.ets`(已 gitignore),编进构建包。**可接受的风险** —— 演示是受控环境,用户已确认测试期可以。
- **阶段二(上线)**:**后端代理**。app 不再持有任何密钥,只调 SoMark 自己的域名(`somark.tech`);在 SoMark 后端加一个 LLM 代理端点,由后端在服务端附加百炼密钥再转发。收益:① 密钥永不进客户端;② 服务端可随时轮换密钥、不用发版;③ 可加限流 / 防滥用 / 用量统计。这一步同时修掉 `SOMARK_API_KEY` 的同类暴露。
  - 备选:若不动 SoMark 后端,阿里云函数计算(FC)起一个极小的百炼代理函数亦可 —— 但「全部走 somark.tech 一个域」更干净。
- **归属**:阶段二是上线前工作,不在 2 周演示冲刺内,本次只入路线图。

## 6. 导出功能(纳入路线图,低优先级)

(回应用户「给扫描内容加导出功能,看有无可直接用的华为 SDK,加入规划,可以先不做」。)

**目标**:把解析结果导出 —— 多种格式、图片存相册、文件存系统目录、分享给其他 app。

**华为 SDK 调研**(均为 HarmonyOS NEXT 原生、可直接用):

| 能力 | SDK |
|---|---|
| 图片存相册 | Media Library Kit(`photoAccessHelper`)+ `SaveButton` 安全控件,一键保存免权限申请 |
| 文件存系统目录 | Core File Kit `DocumentViewPicker`(保存对话框,用户选目录) |
| 分享给其他 app | Share Kit(系统分享面板) |
| 生成 PDF | `@kit.PDFKit` —— 已是工程依赖(`PdfBuilder.ets` 在用,有现成模式可扩展) |
| 生成图片 PNG/JPG | Image Kit(结果渲成 PixelMap 再编码) |
| 导出 Markdown / 纯文本 | 无需 SDK,直接写文件 |

**需额外工作的部分**:Office 格式(Word / Excel)**没有华为原生 SDK** —— 需引第三方 ArkTS 库或服务端转换。这是导出里唯一的硬骨头。

**结论**:「往哪存 / 分享」+「PDF / 图片 / Markdown」都有现成 Huawei SDK,工作量可控;Office 格式需独立评估。**优先级 P2(演示后)**,本次冲刺不做。

## 9. 实现顺序(交 writing-plans 细化)

- 共享逻辑(扫描 / SoMarkApi / Store / PdfBuilder)已在 `main`,三 worktree 直接继承,不重复实现。
